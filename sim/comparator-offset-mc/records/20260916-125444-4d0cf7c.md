CORRECTED BY ISSUE #28: on the pinned ngspice-46 toolchain (sim/toolchain.json), `set rndseed=<N>` does NOT seed the stream agauss() mismatch draws are taken from -- two runs of the same deck with the same `set rndseed=` produce different draws (confirmed by direct A/B testing during issue #28: two `ngspice -b` runs of an isolated agauss() probe deck with `set rndseed=12345` printed different values both times). `setseed <N>` (no `set` prefix) is the mechanism that actually seeds that stream on this toolchain -- confirmed to reproduce byte-identical draws across repeated runs, and used here from this record onward. - **Monte-Carlo scope**: mismatch-only. The mos_mismatch corner set (mos_{tt,ff,ss,fs,sf}_mismatch) is both the process-corner axis AND the Monte-Carlo mismatch switch at once -- see sim/harness/corners.py's module docstring for why SG13G2 has no equivalent of a separable global mismatch switch. Global process skew is swept deterministically by the corner axis itself (tt/ff/ss/fs/sf), so the two are never confounded in one number.
- **Sigma derivation**: 1-sigma of the input-referred offset is reported directly, alongside the 3-sigma value a comparator offset spec is conventionally stated at. Statistical precision on each sigma is 1/sqrt(2N) = 5.0% at N = 200. Offset per draw is -dv(0 mV)/A_v where A_v is measured on the SAME draw from the 0 mV and +2 mV points of one `dc` sweep; av_sigma_pct is the check that the draw really was preserved between them.
- **Note**: TWO DC POINTS PER DRAW, ONE INSTANCE. Gain is measured inside a single `dc` sweep of the shared differential source, not from a second instance. Two instances would have independent mismatch draws, so their difference would contain an offset difference rather than just the gain.
- **Note**: WHAT IS NOT IN THIS RECORD. (a) The decision stage's own offset -- it has no DC operating point, so this method cannot reach it at all (this is a structural property of the topology, per DR-0001 Decision Section 3, not a placeholder artefact). (b) The regenerative loop's own contribution to offset -- comparator_dut_analog's front-end load is now real diode-connected PMOS devices (M5A/M6A in design/comparator.spice), not an ideal SPICE resistor, so THEIR local mismatch IS included in sig_vos_mv below (real PDK devices under the mos_mismatch corner set carry the same agauss() mismatch terms the input pair does) -- but diode-connecting those loads breaks the positive-feedback loop by construction, so this record still excludes the cross-coupled regenerative pair's own mismatch/noise contribution entirely (design/README.md's 'comparator_dut_analog is a reduced sub-model' section). (c) Any layout-induced systematic offset -- this is a schematic-level record (no layout exists yet).
- **Note**: THE COMMON-MODE BAND IS +/-50 mV ABOUT dut_vcm AND IT IS A STANDALONE CHOICE. There is no CDAC or SAR sequencer here to inherit a band from; the band is a stated property of the comparator's own input range.
- **Note**: EVERY sqrt() IN THIS BLOCK IS GUARDED WITH abs() (issue #8). A variance term (e.g. svaq/nmax - (sva/nmax)^2) that is mathematically ~0 -- which happens whenever the underlying corner carries no mismatch, e.g. a plain (non-`_mismatch`) `mos_*` corner such as `--corners tt`, or `--sabotage-corners` forcing every corner to `mos_tt` -- can land a few ULPs on the negative side of zero from floating-point summation order. ngspice's sqrt() of a negative real returns a COMPLEX result, printed as `real,imag` (e.g. `0.0000000000e+00,8.0920713114e-14`), which does not match this harness's `m_<name> = <float>` measurement regex at all -- the point then fails as 'no measurements parsed' instead of cleanly reporting sig_vos_mv ~ 0 mV and failing the mismatch-on guard above for the intended reason. sqrt(abs(...)) makes the mismatch-off case report a clean near-zero sigma (still correctly failing the >= 0.05 mV floor) instead of a parse failure. Confirmed empirically during issue #8: sim/characterize.sh smoke uses `--corners tt_mismatch` (not plain `tt`) for this experiment specifically so its 200-draw loop always has real mismatch to measure; `--sabotage-corners` still collapses every corner to plain `mos_tt`, so the guarded formulas are what make its FAIL land on the documented mismatch-on-guard check rather than on a parse error.
