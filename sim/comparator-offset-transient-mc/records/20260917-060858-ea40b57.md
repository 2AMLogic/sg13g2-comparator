This record substantiates that a transient Monte-Carlo digital-staircase offset sweep genuinely runs and genuinely detects SG13G2's per-instance local mismatch across the WHOLE latch (comparator_dut: input pair, tail, cross-coupled regenerative pair, reset devices, isolation inverters, SR output latch) -- STILL NOT evidence toward README.md#target-specification's Offset-sigma row on its own: that ratification is a separate, later act (spec/porting-plan.md's third step in this chain). Unlike comparator-offset-mc, this bench excludes NOTHING from the topology by construction: it is not a lower bound.

- **Monte-Carlo seed / draws**: ngspice `setseed 20260916` (NOT `set rndseed=`) at the top of the control block, then 60 draws per PVT point via `reset` inside a `dowhile` loop -- each `reset` re-evaluates the agauss() expressions inside SG13G2's mismatch-enabled LV MOS model (confirmed during issue #6, sim/device-mismatch-confirm/README.md; the SAME idiom comparator-offset-mc already uses for its own dowhile/reset loop). `setseed <N>`, NOT `set rndseed=<N>`: on the pinned ngspice-46 toolchain (sim/toolchain.json), `set rndseed=` does NOT seed the stream agauss() mismatch draws are taken from -- two runs of the same deck with the same `set rndseed=` produce different draws (established by direct A/B testing during issue #28, fixed for comparator-offset-mc in issue #32; sim/harness/testbench.py now refuses a record_kind='monte-carlo' manifest that uses it). This bench has never committed a record taken on the broken mechanism -- the pre-#32 development runs made while this bench was being written were discarded unrecorded rather than patched, so every number in this experiment's records/ comes from a `setseed` run. The SAME seed is used at every PVT point (common random numbers), so movement of the reported sigma across the grid is a real PVT effect, not sampling noise. N for statistical-error purposes is 60, not 60 x 45; 1/sqrt(2N) = 9.1% statistical precision on each reported sigma (comparator-offset-mc's N=200 gives 5.0% -- this bench's per-draw cost is far higher, a full 990 ns / 33-level staircase transient instead of one 6-point dc sweep, so N is smaller; see README.md 'Why N=60, not N=200').
- **Monte-Carlo scope**: mismatch-only, identical scope convention to comparator-offset-mc: the mos_mismatch corner set (mos_{tt,ff,ss,fs,sf}_mismatch) is both the process-corner axis AND the Monte-Carlo mismatch switch at once (sim/harness/corners.py's module docstring). Global process skew is swept deterministically by the corner axis; the two are never confounded in one number.
- **Sigma derivation**: 1-sigma of the input-referred offset is reported both raw (sig_vos_raw_mv, includes the staircase's own quantization noise) and quantization-corrected (sig_vos_mv = sqrt(raw_variance - step_variance), step_variance = (3 mV)^2/12 = 7.5e-7 V^2 for this bench's 3 mV level spacing -- the standard uniform-quantization-noise deconvolution, the same correction a flash-ADC-style threshold detector needs). vos_3sig_mv is the corrected 3-sigma value a comparator offset spec is conventionally stated at.
- **Note**: METHOD: A DIGITAL STAIRCASE, NOT A DC SWEEP OR A PER-DRAW BISECTION. comparator_dut has no DC operating point (DR-0001 Decision Section 3) so a `dc` sweep -- comparator-offset-mc's method -- cannot reach it. A per-draw bisection search (several short `tran` sub-runs per draw, narrowing toward the flip point) was considered and rejected: ngspice only re-rolls SG13G2's agauss() mismatch terms on `reset`, and `reset` also restarts the transient clock, so holding ONE draw's mismatch fixed across several bisection sub-runs is not achievable with this harness's control-block idiom. Instead: ONE reset (one mismatch draw), ONE 990 ns transient sweeping 33 discrete differential-input levels (-48 mV to +48 mV, 3 mV/step, 30 ns/step -- the exact strobe cadence comparator-regeneration already validates: 10 ns reset, 10 ns evaluate, 10 ns settle before the next level's input change), with the held, supply-normalized decision output sampled once per level after that level's strobe has closed. Because every level's decision is a genuinely independent, freshly reset strobe cycle (comparator-regeneration's own 'every instance decides both ways' property already proves reset clears the prior decision on this exact DUT), a monotonic near-binary staircase results, and the offset is extracted as: lowcount = (number of levels reading LOW), vos = DV_MIN + (lowcount - 0.5)*DV_STEP. Because the decision output is near-rail (not exactly 0/1) close to the true crossing (a metastable-adjacent level reads an intermediate voltage rather than a clean rail), the sum lowcount is not exactly an integer near the true crossing, which gives a small free sub-step interpolation on top of the DV_STEP quantization -- not needed for validity (the explicit quantization-variance subtraction above already accounts for the coarse case) but improves the estimate.
- **Note**: WHAT THIS RECORD ADDS OVER comparator-offset-mc. comparator-offset-mc's comparator_dut_analog is a diode-connected, loop-broken reduced sub-model that structurally excludes the cross-coupled regenerative pair's own local mismatch and the reset devices' own local mismatch. This bench's comparator_dut is the unmodified DR-0001 topology -- every device that participates in a real decision (input pair, tail, cross-coupled PMOS/NMOS regenerative pair, reset devices, isolation inverters, SR output latch) carries its own agauss() mismatch draw on every `reset`, and all of it is exercised on every one of this bench's 33x60 decisions per PVT point.
- **Note**: WHAT IS STILL NOT IN THIS RECORD. (a) Any common-mode dependence of the whole-latch offset -- this bench sweeps only the differential axis at the DUT's own dut_vcm; comparator-offset-mc's +/-50 mV common-mode sweep has no analogue here yet (a named, not-yet-specified extension, see README.md). (b) Any layout-induced systematic offset -- this is a schematic-level record (no layout exists yet). (c) Dynamic (regeneration-noise-driven) metastability spread -- this bench uses NO transient noise sources (`.control`'s dowhile/reset loop only re-draws static agauss() mismatch, never thermal/flicker noise), so it reports the mismatch-driven offset distribution only; the noise-driven decision-time/metastability spread is issue #24's separate transient-noise bench, not this one.
- **Note**: EVERY sqrt() IN THIS BLOCK IS GUARDED WITH abs(), the same numerical-precision discipline comparator-offset-mc's tb.json documents (issue #8): a variance term that is mathematically ~0 (a collapsed, mismatch-free population, e.g. under --sabotage-corners) can land a few ULPs negative from floating-point summation order, and ngspice's sqrt() of a negative real returns a COMPLEX result that this harness's `m_<name> = <float>` regex cannot parse at all.
