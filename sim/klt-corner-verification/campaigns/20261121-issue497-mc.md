# Stored Monte-Carlo evidence for the issue #497 capacitance screens (campaign `20261121-issue497`)

The committed campaign directory
`sim/klt-corner-verification/campaigns/20261121-issue497/` carries, for each
candidate setting (`scr_cadd1f`, `scr_cadd2f`, `scr_cadd4f`), the full
request/body/invocation/attempts chain, the deterministic 18-point
regeneration envelopes (with their per-corner ngspice artifacts) and the
study report (`capacitance.{json,md}`). The bulky Monte-Carlo evidence of
the Row 2 screens is stored here instead of committed, under the
evidence-size budget (issue #318): this run id holds each setting's three
transient_noise screening envelopes (N = 80 trials per rung, seed = the
bench default 20260916 committed in each request) plus the per-corner
ngspice artifacts of those nine parts. Every stored `name` maps 1:1 onto the
committed campaign directory of the same setting: `scr_<name>/` here is
`20261121-issue497/scr_<name>/` there.

Headline screen results (18-point grid, `kltsim.cap_screen`, seeds
committed; full validated tables in `20261121-issue497/capacitance.md`):

| setting | C per side [fF] | noise mean sigma [mV rms] (valid/18) | worst t_d @ 0.1 mV [ns] | decision |
|---|---:|---:|---:|---|
| control (`ib10_sw20lat6`, archived `20261115-issue92-bias`) | 0 | 1.05259 (18/18) | 1.862 @ ss_-40c_1.08v | - |
| cadd1f | 1 | 1.041 (18/18) | 1.880 @ ss_-40c_1.08v | eliminate |
| cadd2f | 2 | 1.022 (18/18) | 1.899 @ ss_-40c_1.08v | eliminate |
| cadd4f | 4 | 1.025 (18/18) | 1.936 @ ss_-40c_1.08v | eliminate |

**Negative result: no setting advanced.** The best observed noise deficit
(2.9 % at 2 fF) is roughly half the 5.0 % reduction reaching 1.0 mV requires
and sits at the screen's own sampling floor (paired per-point SE ~3 %), the
2 fF and 4 fF deficits are indistinguishable (saturation), while Row 3c
rises monotonically (+1.0 % / +2.0 % / +4.0 %) toward the 2.0 ns limit. The
Phase 1 calibration ([stored
separately](../../comparator-integration-capacitance/reports/20261121-issue497-calibration/README.md))
shows the added capacitance leaves the input-referred white density and the
DC gain unchanged, so the small observed reduction is a pure
decision-bandwidth effect that saturates far short of the Row 2 Target. No
candidate from this family closes Row 2 within the Row 3c limit; the
full-grid Rows 1-5 stay unmeasured for every setting.

ngspice's TRNOISE generator ignores klt's per-sample `.options seed=`
([klayout-tools#2963](https://github.com/2AMLogic/klayout-tools/issues/2963)),
and separate transient sources cannot be independently seeded
([klayout-tools#5772](https://github.com/2AMLogic/klayout-tools/issues/5772)):
most screening samples (1264-1368 of 1440 per setting) repeat a raw noise
draw also seen at another grid point, exactly as the archived control
campaign's notes record. Each point's estimate stays valid and unbiased;
the points are not mutually independent, which widens the grid mean's
sampling error and is one more reason the screen treats ~3 % differences as
its floor. The grader's independence checks (per-point duplicate draws,
missing raw-noise probes) all passed: 18/18 valid points per setting.

```
python3 scripts/check_artifact_manifests.py verify manifests/artifacts/klt-corner-verification-20261121-issue497-mc.manifest.json
```

Reproduce: `python3 sim/run_klt_corner_verification.py build/run` per
setting (see `sim/comparator-integration-capacitance/README.md`), then
`capacitance --campaign 20261121-issue497`. To re-derive the screen from
these bytes, fetch each setting's three
`scr_<setting>/transient_noise.mos_<proc>.envelope.json` back into the
committed campaign directory and re-run the `capacitance` command.
