# Stored Monte-Carlo evidence for the issue #498 PMOS load-width study (campaign `20261121-issue498`)

The committed campaign directory
`sim/klt-corner-verification/campaigns/20261121-issue498/` carries, for each
candidate (`scr_w4`, `scr_w8`, `scr_w10`, `scr_w12`) and the advanced
finalist (`full_w10`), the full request/body/invocation/attempts chain, the
deterministic 18/45-point kickback and regeneration envelopes (and their
per-corner artifacts), the grading outputs and the study reports
(`loadwidth.md`, `sizesweep.md`, `sizesweep-final.md`). The bulky
Monte-Carlo evidence is stored here instead of committed, under the
evidence-size budget (issue #318): this run id holds each candidate's three
transient-noise screen envelopes (N = 80 per rung, seeds = bench defaults
committed in each request), the finalist's five offset_mc (N = 60) and five
transient_noise (N = 80) envelopes, plus one `artifacts-mc.tar.gz` per
directory with the per-corner ngspice artifacts of those benches. Every
stored `name` maps 1:1 onto the committed campaign directory of the same
sub-campaign: `full_w10/` and `scr_<name>/` here are
`20261121-issue498/full_w10/` and `20261121-issue498/scr_<name>/` there.

Headline results (unchanged bench, 36.27 nV/rtHz injection): the 18-point
Row 2 screen means were 1.076 / 1.065 / 1.008 / 1.032 mV rms for w4 / w8 /
w10 / w12 against the control's 1.053; the advanced finalist w10 grades
1.041 mV rms on the full 45-point grid (Target <= 1.0 NOT met), with every
other Target row PASS at 45/45 valid points. See `loadwidth.md` and
`sizesweep-final.md` in the committed campaign for the full tables and the
advance/eliminate reasons.
